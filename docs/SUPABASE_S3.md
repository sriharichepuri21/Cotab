# Supabase S3-compatible Storage setup (ReceiptWise)

Supabase Storage exposes an **S3-compatible API** on the free 1 GB plan — that
lets ReceiptWise keep using boto3 with zero code changes.

## 1. Create the project + bucket

1. https://supabase.com → New project → pick region, save the **DB password**.
2. SQL Editor → run once (creates tables lazily… actually the app does
   `CREATE TABLE` itself on boot; Supabase needs **nothing** pre-created).
3. Storage → New bucket → name **`receiptwise-uploads`**, private (not public).

## 2. Get S3 credentials

Dashboard → Project Settings → Storage → **S3** (or "Connection info"):

```
Endpoint URL:  https://<project-ref>.supabase.co/storage/v1/s3
Region:        <same-as-project-region>  (not used by boto3, any value OK)
Access Key ID: (click "Generate new S3 key")
Secret Access Key: (shown once)
```

## 3. Map to the app's env vars

```
S3_ENDPOINT_URL=    https://<project-ref>.supabase.co/storage/v1/s3
AWS_ACCESS_KEY_ID=  <supabase s3 access key>
AWS_SECRET_ACCESS_KEY=<supabase s3 secret>
AWS_DEFAULT_REGION= us-east-1           # placeholder; Supabase ignores it
S3_BUCKET=          receiptwise-uploads
```

Notes:

* Presigned GET URLs generated by boto3 work unchanged against the Supabase S3 endpoint.
* Keep the bucket **private**; always serve images via presigned URLs.
* On free tier you get 1 GB of file storage + 2 GB bandwidth/month — plenty for MVP (~150 KB per receipt ≈ 6,500 receipts).

## 4. Database DSN

Supabase → Project Settings → Database → Connection string → URI.
Replace the password placeholder; it already starts with `postgres://`
(the app normalizes that to SQLAlchemy's `postgresql+psycopg2://` form).
